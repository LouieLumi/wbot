| --- | --- |
| Node.js | 22.13+，使用内置 `node:sqlite` |

## 已有验证

项目开发期间完成过真机群消息读取、模型回复、代码文字发送、图片发送及服务端回执检查；Gemini 网页也完成过真实群命令到图片发送的链路。测试用账号、群名、消息、图片和设备标识不随仓库发布。

1.1.1 针对 Gemini 重建消息节点后结果定位超时进行了回归测试，并在真实已生成页面验证结果定位。发布时该修复后的新请求全流程复测仍待完成，不能把旧版本成功记录视为本版本验收。

## 每次新部署应验收

1. mock 模式能启动、管理页可登录、`npm run check` 通过。
2. 手机接口身份与版本正确，未授权群无法调用普通收发。
3. `/signup` 只创建待授权记录；批准后才回复。
4. 管理员在不同群权限一致，普通成员无法调用管理命令。
5. 不同成员上下文隔离；重置后旧待发回答失效。
6. 真实文字与图片均取得 `wechat_server_ack`。
7. 图片 A → B → A 使用各自会话；`/newimg` 只重开自己的会话。
8. 断连、超时、暂停和重新登录后不重复发送旧任务。

系统休眠、退出当前桌面用户会话、USB 中断、Android 锁屏、微信退出登录、Gemini 额度耗尽或网页变更都可能使工作中断。代码通道和网页通道的锁屏行为应分别验证。

### 1.2.0 队列更新

新增 SQLite 提示词队列、排队任务重启恢复、新文档派发握手，以及动态输入框/发送按钮的回归测试。升级需重新加载桌面的 Gemini 扩展；旧协议不会继续领取任务。真实多人网页验收结果以部署后的测试为准。

### 1.2.1 图片下载更新

图片下载显式使用浏览器登录态；对当前已生成资源最多尝试三次，失败记录下载阶段和 HTTP 状态，不重复提交提示词。1.2.0 已观察到两次真实请求生成图片并收到微信发送确认；后续一次图片生成后的下载失败推动了本次修复。后续真实下载验证见 1.2.4。

### 1.2.2 工作页恢复

工作标签页被重建时复用已有专用页，并恢复尚未派发任务的目标对话；提交前的导航失败最多尝试三次。已经派发或生成中的任务不会自动重放，失败结果在服务端确认后才释放队列。新增标签页恢复、导航失败、重试上限和中断去重测试。

### 1.2.3 导航诊断

记录工作页导航、刷新异常，保留有限次数的提交前重试。增加受本机 worker Token 保护的空闲重载入口，避免每次更新都需要手动打开扩展管理页。

### 1.2.4 导航提交确认

`chrome.tabs.update` 完成不代表新地址已提交。切换同一路径的任务片段后，先确认目标 URL 已加载且无待提交导航，再刷新以建立新文档，避免刷新取消地址切换、返回旧工作页。新增模拟延迟导航提交的回归测试。

2026-10-15 实测：扩展由本机接口重载至 1.2.4；已有会话中的图片数据回传成功（JPEG，116,713 字节）；独立红苹果任务完整通过提示词填写、提交、生成与下载（JPEG，29,916 字节）。诊断任务未创建微信群发送记录。旧的直接下载地址不可用时，应检查当前页面中的图片数据，不能据此判定新生图同样失败。

随后，同一群成员连续发起苹果、鸭梨两条真实 `/img` 请求，两条任务均完成，图片发送记录均为 `sent / wechat_server_ack`，验证了生成、回传以及同一成员会话续接后的微信图片发送。

### Android API 5：文字发送回执

移除旧模块每次启动累计 100 条文字发送的限制。发送前将任务 ID、群 ID、正文摘要及状态写入微信私有目录，取得服务端回执后更新状态；微信重启后仍保留去重记录，不保存正文。不确定任务不自动重发，ID 与群或正文冲突时拒绝发布。磁盘不可写或已有回执损坏时停止该请求。

新增独立 JVM 回归检查：连续 250 条请求、早期回执保留、进程重启、并发去重、载荷冲突、回执损坏和存储失败。该检查不连接手机或发送微信消息；真机更新和发送回执须另行验证。

2026-10-15：89 项服务测试及 7 组回执检查通过。真机完成同签名覆盖更新，接口返回 API 5 与持久化回执标记，数据库连接、原有群授权和自动回复设置正常。随后，群成员发起新的问候请求，模型生成文字回复，发送任务取得 `sent / wechat_server_ack`，完成更新后的真实收消息、生成回答及微信文字送达验证。

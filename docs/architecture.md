# 架构

## 当前代码通道

Android 微信模块监听本版本的消息数据库写入，提取授权群中触发机器人的消息、真实群 ID、发送者 ID、消息 ID 和时间。手机仅绑定 loopback，经 ADB 转发后由 `AndroidHookDriver` 使用 Bearer Token 访问。代码通道不使用视觉适配器，也不因失败自动回退。

手机的 `/signup` 申请可在群未授权时登记；普通消息仍受独立授权集合限制。后台批准后同步群 ID。群名仅用于显示，两个同名群仍是两个独立群。

## Bridge

Bridge 协调入站去重、授权、统一管理员、成员记忆、命令与发送队列。普通文字和图片分别排队；一组图片任务不会阻塞普通文字回复。设备发送串行执行。

SQLite 表包含 `groups`、`members`、`turns`、`jobs`、`reply_context`、`job_images`、`image_sessions`、`image_reply_context` 与设置、鉴权相关表。成员按真实微信账号派生 ID 跨群共享个人记忆；昵称改变不合并或覆盖其他人的数据。修改或重置记忆增加 revision，使尚未发送的旧回答失效。

代码模式的 `sent` 需要手机端检查微信消息状态为 2 且服务器消息 ID 存在。发送预约先落盘，相同任务 ID 重用原回执；网络中断或进程重启留下的模糊状态标为 `uncertain`，不自动重发。只有已确认且记忆版本有效的回答提交到上下文。

## 文本模型与搜索

Ollama 直接调用本机 `/api/chat`。Hermes 在独立 Python 子进程执行一次会话，加载该成员独立的原生 MemoryStore 与 SessionDB，在临时 profile 中整理记忆，微信确认发送后才提交。不会载入操作者的私人 profile、SOUL 或上下文文件。工具严格限于 `memory`、`group_recall` 和可选的 `web_search`。

模型按个人覆盖、群默认、后台默认的顺序选择。管理员的模型切换和成员的记忆重置有独立的权限与任务失效规则。模型介绍只包含机器人名字和实际选择的模型。

## 图片

服务器向鉴权的本机图片 worker 分配随机任务 ID 与会话 ID。Chrome 扩展保存 `会话 ID → Gemini 对话 URL`，一个专用标签页串行处理。对话绑定到“群 + 成员”；同一成员跨群也隔离。

提交前校验完整输入和可用发送按钮，点击后确认新用户消息。取结果时按本轮提示词与轮次重新定位，允许 Gemini 重建 DOM，排除旧图和其他轮次。有效图片优先，模型只返回文字时转回文字。图片原始字节回传 Bridge，再由手机图片服务发送，不截屏。

`/newimg` 切换随机会话 ID，取消该成员旧排队任务与生成任务。暂停、撤销授权、成员停用或 revision 改变也会阻止尚未发送的结果。

## 管理端

Fastify 提供本机 REST、WebSocket 和静态管理页面。Bearer Token 与 Cookie 均可鉴权；密码经 scrypt 加盐，登录失败限流。一次性登录票据有效 60 秒；会话有效 12 小时并持久化，重设密码会注销旧会话。Host、Origin、CSP 和同源限制共同保护本机接口。

## 历史适配器

`adb` 模式及 `scripts/vision_device.py` 保留为旧研究实现，身份与发送证据弱于代码模式。旧视觉群和成员记录不与真实微信 ID 自动合并。通知诊断 App 仅评估通知/无障碍能力，不参与当前自动回复通道。

## 生图队列

`image_requests` 在本机 SQLite 保存完整提示词、群成员、会话 ID 和递增排队序号。全局逐个调用生图服务，只有轮到当前任务时才发送到浏览器；排队时间不占用该任务的生成超时。文本回复不等待图片队列。

扩展 1.2.0 使用协议 3：导航到成员所属对话后等待新文档，确认页面接收任务，再填写完整草稿、等待发送按钮可用并验证新用户消息。相同会话连续请求也刷新专用页面；不能把旧页面的输入框当作新任务已就绪。结果上传得到服务端确认后才释放当前任务。

服务重启后仅恢复尚未调用生图服务的 `queued` 请求；中断中的 `running` 请求标记为 `uncertain`，避免重复生图。恢复和执行时再次验证群授权、成员版本和生图会话。`/newimg` 仍只作废该成员旧会话的请求。


## 群文字记录与召回

手机 API 6 的 `GET /history` 使用固定只读 SQL，仅查询当前已授权群的入站 type=1 文字，按 `msgId` 分页（每页最多 100 条）。它与仅接收 @/命令的事件队列独立，历史消息永远不会进入自动回复路径。首次启用补入最近 24 小时；之后 SQLite 在同一事务中写入 `group_messages` 并推进 `group_capture` 游标，手机或服务重启可以补齐尚留在手机数据库中的记录。账号数据库来源摘要参与唯一键，游标与来源不匹配时重读去重。取消授权停止采集；重新授权只接收重新授权后的消息，旧记录保留。全局暂停期间不轮询，恢复后补齐仍然授权的群；群内 `/stop` 仅停回复，记录继续采集。

群原文存放于本机 SQLite，不逐条调用模型、不导入成员个人记忆。Hermes 的 `group_recall` 根据当前问题按北京时间、关键词、分页读取这一群的历史。工具不接受群 ID 或 SQL 参数，群范围由服务固定，并在每次查询时验证授权。返回数据有发言者、时间、记录范围、同步状态和截断标记；不含图片与语音内容。记录保存从启用时的最近一天开始，不宣称覆盖加入前、被删除或未授权期间的聊天。

任何调用过 `group_recall` 的模型轮次都标记为 group：禁用该轮后续个人 memory 写入与 web_search，丢弃个人记忆草稿；只有发送确认后，才将问答保存到 `group_answers`，不会写入成员跨群 SessionDB。后续在同一群召回可查最近两次自己的群问答。个人偏好仍由原生 Hermes 按微信成员独立管理。后台的“群聊记录”供管理员查看最近 100 条与同步状态。

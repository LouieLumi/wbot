# 私聊链接翻译与频道发布

入口是个人微信 **Nila 的好友私聊**；出口是企业微信机器人 **D.va 的频道独立帖子**。不会把群里的链接自动发布，也不会监听企业微信私聊。

## 使用

1. 私聊 Nila 发送网页链接，或普通网页分享卡片。
2. Nila 询问是否翻译并发布，给出八位任务编号。
3. 回复 `确认 编号` 开始；回复 `取消 编号` 放弃。只有一条待确认任务时可省略编号。
4. 翻译完成后发布到配置的频道，并私聊通知结果。

`待处理` 或 `状态` 查看自己最近十条任务。确认有效期为 24 小时。不同用户不能确认彼此的任务；一次最多三条链接，每人最多十条未完成任务。确认之前不读取网页，不调用模型。

发布保留中文标题、章节、段落、列表、引用、代码及原文地址，并提取正文中的原图。网页图片按原文顺序下载并上传到企业微信，文字与对应图片组成一个内容段；后续图文作为同一帖的回复继续发布。当前使用原生 `image_list`，图片展示在该段文字下方，不依赖外链图片渲染，也不承诺能在一个正文内任意插图。正文超过单条 20480 字节上限时也会拆段，长文不静默截断。

提取支持相对图片地址、常见懒加载属性和 `srcset`，跳过正文以外的导航和尺寸明确的跟踪像素。图片不交给模型生成或改写，图的位置和地址由程序保留。单张下载最多 10 MB，当前识别 PNG、JPEG、GIF、WebP；如果原站拒绝下载、格式不支持或平台上传失败，则在对应位置保留原图链接，并在私聊结果中说明数量。正文最多 80 个图片位置，超过时明确失败，不悄悄丢弃后面的图。

正文获取、模型截断、段落缺失或平台拒绝会返回失败；网络断开导致发送结果不确定时不自动重新发帖。所有文字译完、图片准备完后才开始发帖；不会边翻译边发出半篇正文。

## 部署

需要 Android 模块 API v7（`private_links_supported=true`）、已运行的 Nila 服务、已加入目标频道且有主动发帖权限的企业微信机器人。

复制 `config/link-publisher.example.json` 到 **已忽略的** `data/link-publisher/config.json`，填入凭据、已验证的频道 ID 和允许使用的微信号。不要把真实凭据写入模板或 Git。`wechat_accounts` 使用微信号，启动时通过手机联系人中的精确账号/别名解析，不按昵称匹配。

当前全局管理员也可沿用 Nila 数据库里已验证并固定的微信成员 ID；联系人暂未提供微信号别名时不会丢失这个绑定。新的解析结果若与固定身份冲突，则停止接入。

尚无身份绑定时，部署者可以在私有配置里设置一次性 `pairing`（`content` 为 `绑定发帖 ` 加八位随机十六进制、毫秒 `issued_at` 与 `expires_at`）。有效期最多 30 分钟；用户从好友私聊发出完全相同的文字，手机只匹配这条新消息，服务保存固定身份。不会用群发言配对，也不会据此改变现有机器人管理员配置。

```bash
npm ci
npm run build
python3 scripts/link-publisher-service.py install
python3 scripts/link-publisher-service.py status
```

安装路径：`~/Library/Application Support/NilaLinkPublisher`，服务名 `local.nilabot.link-publisher`。程序复用 `bridge_root` 中的手机配置、本机模型端点和当前默认模型；正文翻译独立调用模型，不载入个人/群聊记忆。Nila 全局暂停时停止接受和发布任务，已准备好的译文保留等待恢复。

手机负责微信收发；Mac 提取网页正文，并通过现有模型接口把正文交给 Gemini 等当前配置的模型。提取完成后不会先改写成摘要：正文保存成有顺序的内容块，待译文字按约 14000 UTF-8 字节分批传入，要求返回带原始 ID 的 JSON。程序逐项核对数量、次序和 ID，再按原网页结构生成频道 Markdown；模型只负责文字翻译，不负责排列图片或生成图片地址。代码块原样保留。全部批次完成后才组装结果，任一批次截断、缺项、请求失败或明确返回拒绝都会停止任务。

私有配置可增加 `translation_model` 为链接翻译单独指定模型，型号必须由现有代理实际支持；可用列表可供参考，也应验证实际调用。未设置时跟随 Nila 默认模型，不会因设置此项而改变群聊模型。翻译使用 Nila 的全局 `reasoning_effort` 设置，与 Hermes 的请求方式一致；`auto` 时省略该字段。运行状态文件包含当前翻译型号、推理设置和 `publishing_format: rich_sections`。频道排版独立于群聊回答的纯文本设置。

遇到连接故障或 HTTP 429、500、502、503、504 时，每段最多尝试三次，默认等待 5 秒、15 秒，并遵守接口的 `Retry-After`。接口要求等待超过 60 秒时结束本次尝试，避免提前重试；认证错误、明确拒绝及不完整输出不会反复请求。只重试失败的分段，已经完成的译文保留；等待期间向原用户提示一次，最终仍不可用则明确反馈模型繁忙或连接异常。

更新手机模块沿用项目现有编译、同签名更新流程，不能卸载或清空聊天数据。新模块将私聊授权、历史和发送独立为 `/private/authorization`、`/private/history`、`/private/send`；原有群授权和群消息入口保持独立。

## 运行与验证

数据库保存确认状态、任务、正文分段、平台 ID、手机回复发送 ID，以及各联系人的读取游标。轮询只读取明确授权好友的最近一天文字和 type-5 网页卡片，跳过自己的消息。首次启用不会回复旧私聊。手机回复使用原有持久发送回执，同一发送 ID 重试不重复发送；频道发帖结果不明确时转为待核实。

公开网页使用有大小和超时限制的只读请求，每次跳转重新检查公网地址并固定 DNS 解析结果。不加载脚本、不携带登录 Cookie、不读取本机或局域网地址。需要登录、验证码或 JavaScript 才能显示正文的站点可能无法读取。网页响应上限 4 MB，提取正文上限 12 万字符，超限明确失败。

本机代理若返回 `198.18.0.0/15` 的 Fake IP，会通过固定的 Cloudflare DoH 地址解析该公开域名，再校验并连接真实公网 IP；不会直接放行特殊地址，也不会把链接路径或正文交给 DNS 服务。

同一域名返回多个公网地址时，连接失败会在 45 秒总预算内尝试其他已校验地址；HTTP 拒绝和正文校验失败不会触发地址重试。读取错误码保存在任务记录中。读取 Nila 设置遇到数据库占用时，发帖服务暂缓工作，获取新设置后自动恢复。

```bash
npm run build
npx tsx --test tests/link-publisher.test.ts tests/link-layout.test.ts
npm run check
```

这些测试使用自写文章和模拟模型、微信及频道接口，验证长文从开头到结尾完整传入模型、分段次序及失败时不发布；不会翻译外部文章或发送真实帖子。

企业微信频道 HTTP 协议的实现参照已实测的 [bazaar-compute-node 原生频道实现](https://github.com/yuchanns/bazaar-compute-node/pull/101)，并在本机通过官方 API 的频道名称查询、新帖发送和原文回读验证。该功能不通过普通聊天兼容通道发布。
